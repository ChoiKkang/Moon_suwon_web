# 달빛수원 MVP 기획 문서 **문서 목적:** 공모전 제안서를 실제 개발 가능한 1차 제품 요구사항으로 전환한다. **서비스 한 줄 정의:** 수원화성 야간 데이트를 처음 가는 사용자가 코스를 바로 고르고, 스팟을 순서대로 따라가며, 가벼운 현장 미션과 로컬 정보를 소비할 수 있게 만드는 앱 퍼스트 관광 서비스 **문서 상태:** Approved Design v1 **작성일:** 2026-05-25 --- ## 1. 배경 및 문제 정의 수원화성 일대는 야간 관광 잠재력이 높지만, 실제 사용자 관점에서는 다음 문제가 있다. - 어디를 어떤 순서로 가야 하는지 한 번에 보이지 않는다. - 야경 명소의 의미, 포토 포인트, 이동 흐름이 분산되어 있다. - 현장에서 바로 따라갈 수 있는 데이트형 코스가 부족하다. - 지역 상권 정보가 관광 동선 안에서 자연스럽게 연결되지 않는다. 달빛수원 MVP는 이 문제를 `코스 중심 경험`으로 해결한다. 사용자는 지도에서 직접 계획을 세우는 대신, 홈에서 추천 코스를 고른 뒤 스팟을 순서대로 따라가며 야간 데이트를 바로 시작할 수 있어야 한다. ## 2. 제품 목표 1차 MVP의 목표는 기능 확장이 아니라 `핵심 사용자 경험 검증`이다. - 수원화성을 처음 방문한 20~30대 일반 관광객과 커플이 1분 안에 코스를 시작할 수 있어야 한다. - 사용자는 별도 회원가입 없이 코스, 스팟, 미션, 외부 길찾기를 바로 사용할 수 있어야 한다. - 코스 소비 경험은 `야경`, `포토스팟`, `가벼운 체험`에 집중해야 한다. - 관광공사 공공데이터와 자체 큐레이션 데이터를 결합하는 구조를 만들어야 한다. - 이후 반려동물 전용 서브코스를 추가할 수 있도록 데이터 구조를 선행 설계해야 한다. ## 3. 핵심 타깃 사용자 ### 3.1 1차 핵심 타깃 - 수원화성을 처음 방문한 20~30대 일반 관광객 - 데이트 또는 야간 산책 목적의 커플 사용자 ### 3.2 사용자 니즈 - 오늘 밤 바로 갈 수 있는 코스를 빠르게 고르고 싶다. - 사진이 잘 나오는 스팟을 알고 싶다. - 너무 많은 역사 설명보다 짧고 감성적인 현장 가이드를 원한다. - 길찾기는 익숙한 지도 앱으로 넘기고 싶다. - 카페, 디저트, 쉬어갈 곳을 코스 흐름 안에서 보고 싶다. ### 3.3 이번 MVP의 비핵심 타깃 - 반려동물 동반 관광객 반려동물 사용자는 이번 MVP의 메인 타깃은 아니지만, 이후 전용 서브코스를 출시할 예정이므로 데이터 구조와 운영 규칙은 처음부터 반려동물 확장을 고려해 설계한다. ## 4. 제품 원칙 - `코스 우선`: 지도 탐색보다 추천 코스 진입이 먼저다. - `비회원 우선`: 로그인은 진입 조건이 아니라 저장 수단이다. - `가벼운 미션`: 긴 스토리텔링보다 짧은 현장 체험이 우선이다. - `외부 길찾기`: 내비게이션은 직접 만들지 않고 카카오맵/네이버맵 등 외부 앱으로 연결한다. - `앱 퍼스트`: 메인 사용 경험은 앱에서 제공하고, 모바일 웹은 공유와 유입 연결 역할에 집중한다. - `반려동물 확장 대비`: 1차 UI에는 노출하지 않더라도 반려동물 관련 메타데이터는 처음부터 구조에 포함한다. ## 5. 출시 범위 ### 5.1 포함 범위 - 앱 퍼스트 서비스 - 모바일 웹 연동 가능한 코스/스팟 상세 페이지 - 추천 코스 3개 - 핵심 스팟 8~10개 - 스팟별 야간 포인트, 포토 포인트, 짧은 체험 카드 - 코스 진행 상태 관리 - 위치 자동 감지 + 수동 체크 하이브리드 미션 - 외부 지도 길찾기 연동 - 로컬 스팟 정보 노출 및 외부 링크 - 비회원 사용 - 코스/스팟 찜 - 찜 또는 진행 기록 저장 시 로그인 유도 ### 5.2 제외 범위 - 앱 내부 턴바이턴 길안내 - 쿠폰, 예약, 결제 - 사진 업로드 인증 - 리뷰, 평점, 댓글, 동행 커뮤니티 - 실시간 채팅 - 개인화 추천 엔진 - 반려동물 전용 홈 진입 - 반려동물 전용 서브코스 공개 운영 ## 6. 초기 운영 범위 ### 6.1 추천 코스 3종 - `처음 가는 수원화성 데이트 코스` - 첫 방문자용 입문 코스 - 야경 감상과 무난한 이동 동선이 핵심 - `야경 사진 집중 코스` - 포토스팟 중심 코스 - 사진 각도, 뷰 포인트, 머무름 가치가 핵심 - `산책 후 행리단길 마무리 코스` - 성곽 산책 후 카페/식사 동선까지 이어지는 코스 - 데이트 마감 경험이 핵심 ### 6.2 초기 스팟 풀 MVP 운영 스팟은 수원화성 일대의 야간 체험성이 높은 장소로 제한한다. - 화성행궁 - 화홍문 - 방화수류정 - 용연 - 장안문 - 창룡문 - 연무대 - 서장대 - 팔달문 - 행리단길 최종 코스 편성은 이 스팟 풀 안에서 코스별 4~5개 지점으로 구성한다. ## 7. 정보 구조 ### 7.1 하단 탭 구조 - `홈` - 추천 코스 진입의 메인 허브 - `내 주변` - 현재 위치 기준 근처 스팟 보기 - `찜` - 저장한 코스/스팟 확인 - `마이` - 로그인, 기본 설정, 기록 확인 ### 7.2 주요 화면 흐름 - 홈 → 코스 상세 → 코스 시작 → 스팟 진행 → 코스 완료 - 홈 → 스팟 상세 → 외부 길찾기 - 홈/상세 → 찜 → 로그인 유도 - 공유 링크 → 모바일 웹 상세 → 앱 열기 또는 앱 설치 유도 ## 8. 핵심 사용자 흐름 1. 사용자가 앱을 실행한다. 2. 홈에서 추천 코스 3개 중 하나를 본다. 3. 코스 상세에서 소요 시간, 스팟 수, 추천 시간대를 확인한다. 4. `코스 시작`을 누른다. 5. 위치 권한이 있으면 현재 위치 기반 진행을 시작하고, 권한이 없으면 수동 진행 모드로 시작한다. 6. 각 스팟에 도착하면 앱이 반경 진입을 감지해 자동 완료를 시도한다. 7. 자동 감지가 실패하거나 위치 권한이 없으면 사용자가 `직접 체크하기` 버튼으로 동일 단계를 완료한다. 8. 완료 직후 짧은 체험 카드가 노출된다. 9. 다음 스팟 이동 시 외부 지도 앱으로 길찾기를 연다. 10. 마지막 스팟까지 완료하면 코스 완료 화면에서 찜, 공유, 로그인 유도를 제공한다. ## 9. 화면별 요구사항 ### 9.1 홈 홈은 NOL 같은 앱 감성을 참고하되, 정보 과밀도 대신 `코스 진입 속도`를 우선한다. - 상단에는 서비스 한 줄 메시지와 현재 시간대에 맞는 코스 CTA를 배치한다. - 첫 화면 최상단에는 추천 코스 3개를 카드형으로 노출한다. - 코스 카드에는 제목, 한 줄 설명, 예상 소요시간, 스팟 수, 대표 이미지가 들어간다. - 그 아래에는 `지금 가기 좋은 스팟`, `포토스팟 추천`, `근처 로컬 스팟` 섹션을 배치한다. - 비회원 사용자에게는 사용을 막지 않고, 특정 시점 이후 `찜을 저장하려면 로그인` 배너를 노출한다. ### 9.2 코스 상세 - 코스 제목, 설명, 소요시간, 도보거리, 추천 시작 시간, 스팟 수를 노출한다. - 스팟 순서를 리스트로 보여준다. - 각 스팟에는 짧은 요약과 기대 포인트를 표시한다. - `코스 시작` 버튼이 메인 CTA다. - `찜` 버튼을 함께 제공한다. ### 9.3 진행 화면 - 현재 진행 중인 스팟, 전체 중 몇 번째 스팟인지, 다음 스팟 이름을 표시한다. - 위치 자동 감지 상태를 보여준다. - 감지 성공 시 `도착 완료` 상태로 바뀌고 체험 카드가 열린다. - 감지 실패 시 `직접 체크하기` 버튼으로 동일 상태 전환이 가능해야 한다. - 다음 스팟 이동 버튼은 외부 지도 앱 길찾기 액션으로 연결된다. ### 9.4 스팟 상세 - 관광지 기본 정보 - 야간 포인트 설명 - 포토 포인트 설명 - 짧은 스토리 또는 커플 대화형 체험 카드 - 주변 로컬 스팟 정보 - 외부 길찾기 버튼 - 찜 버튼 ### 9.5 찜/마이 - 비회원도 찜 버튼은 누를 수 있다. - 장기 저장 또는 기기 간 동기화가 필요한 시점에 로그인 유도 모달을 보여준다. - 마이 화면은 출시 초기에는 최소 범위로 운영한다. - 포함 항목은 로그인, 위치 권한 상태, 찜 보기, 최근 진행 코스 정도로 제한한다. ## 10. 미션 설계 ### 10.1 미션 원칙 - 미션은 `짧고 즉시 수행 가능한 체크형`으로 통일한다. - 미션 자체는 복잡하게 만들지 않는다. - 자동 위치 인식은 편의 기능이고, 미션의 본질은 현장 경험 유도다. ### 10.2 완료 방식 - 기본 방식: 위치 반경 진입 시 자동 완료 시도 - 보조 방식: 수동 체크 버튼으로 완료 ### 10.3 권장 판정 규칙 - 기본 반경은 스팟별 80m 내외로 시작한다. - 개방형 성곽 구간은 100m까지 완화할 수 있다. - 밀집 구역이나 출입 포인트가 분명한 장소는 60m까지 좁힐 수 있다. - 자동 완료가 1회 이상 실패해도 사용자는 항상 수동 체크로 진행 가능해야 한다. ### 10.4 체험 카드 유형 - 포토 미션 - 예: 특정 구도로 사진 찍기 - 감상 포인트 - 예: 성곽 라인, 수면 반사, 조명 포인트 보기 - 짧은 스토리 - 예: 정조 관련 한 줄 맥락 - 커플 질문 - 예: 서로 한 문장씩 답하는 질문 ## 11. 데이터 구조 ### 11.1 코스 데이터 ```json { "id": "course-night-photo-01", "title": "야경 사진 집중 코스", "subtitle": "방화수류정과 용연 중심의 포토 데이트", "themeTags": ["date", "photo", "night"], "estimatedDurationMin": 120, "walkingDistanceKm": 2.8, "recommendedStartTime": "19:00-20:00", "spotIds": ["spot-banghwasuryujeong", "spot-yongyeon", "spot-hwahongmun"], "petReadyFlag": false } ``` ### 11.2 스팟 데이터 ```json { "id": "spot-banghwasuryujeong", "name": "방화수류정", "category": "heritage-night-view", "lat": 37.2870, "lng": 127.0175, "intro": "수원화성의 대표 야경 포인트", "nightHighlight": "수면 반사와 정자 조명이 함께 보이는 구간", "photoTip": "난간 대신 정자와 수면을 함께 넣는 구도 권장", "missionType": "check", "missionPrompt": "정자와 수면이 함께 보이는 지점을 찾아보세요.", "missionRadiusM": 80, "localLinkIds": ["local-cafe-01"], "petPolicy": "partial", "petNote": "실외 이동은 가능하나 혼잡 시간대 리드줄 관리 필요" } ``` ### 11.3 로컬 스팟 데이터 ```json { "id": "local-cafe-01", "name": "행리단길 카페 예시", "type": "cafe", "summary": "코스 마무리 후 들르기 좋은 디저트 카페", "linkUrl": "https://example.com", "walkingMinutes": 7, "petFriendly": false } ``` ## 12. 데이터 소스 전략 ### 12.1 공공데이터 활용 다음 계열의 한국관광공사 데이터를 기본 정보 소스로 사용한다. - 지역기반 관광정보 - 위치기반 관광정보 - 공통정보, 소개정보, 이미지정보 - 행사정보 - 관광지 집중률/방문자 추이 예측 정보 - 반려동물 동반여행 서비스 데이터 ### 12.2 자체 기획 데이터 공공데이터만으로는 데이트 경험을 만들 수 없으므로 자체 기획 데이터가 반드시 필요하다. - 코스 구성 정보 - 스팟 순서 - 야간 포인트 설명 - 포토 포인트 설명 - 체험 카드 문구 - 로컬 스팟 큐레이션 - 반려동물 관련 운영 메모 ### 12.3 데이터 운영 원칙 - 관광지 기본 정보는 공공데이터를 기준값으로 사용한다. - 경험 설계에 필요한 문구와 큐레이션 정보는 내부 데이터로 관리한다. - 공공데이터와 내부 데이터를 느슨하게 결합해, 추후 코스나 스팟 문구만 별도로 업데이트할 수 있어야 한다. ## 13. 앱 퍼스트와 모바일 웹 연동 정책 - 메인 사용 경험은 앱에서 제공한다. - 모바일 웹은 `공유 링크`, `검색 유입`, `SNS 랜딩` 역할에 집중한다. - 모바일 웹 상세 페이지는 코스와 스팟의 핵심 정보만 제공한다. - 실제 코스 진행, 찜 저장, 위치 기반 미션은 앱에서 사용하도록 유도한다. - 앱이 설치된 사용자는 딥링크로 앱 상세 화면을 연다. - 앱이 없는 사용자는 모바일 웹에서 내용을 본 뒤 앱 설치 또는 앱 열기를 선택한다. ## 14. 반려동물 확장 설계 ### 14.1 MVP 공개 정책 - 반려동물 전용 코스는 이번 MVP에 노출하지 않는다. - 반려동물 전용 필터도 메인 UI에는 노출하지 않는다. ### 14.2 선반영해야 하는 내부 구조 - 모든 관광 스팟에 `petPolicy`, `petNote`를 저장한다. - 로컬 스팟에도 `petFriendly` 여부를 저장한다. - 코스에는 `themeTags`, `petReadyFlag`를 둔다. - 향후 반려동물 전용 서브코스를 만들 때 일반 코스 구조를 재사용할 수 있어야 한다. ### 14.3 향후 확장 방식 - 1단계: 반려동물 가능 여부 필터 공개 - 2단계: 반려동물 동반 가능 로컬 스팟 큐레이션 공개 - 3단계: 반려동물 전용 야간 서브코스 출시 즉, 이번 MVP는 일반 데이트 앱처럼 보이지만 내부 데이터 구조는 이미 `pet-ready` 상태여야 한다. ## 15. 성공 지표 출시 후 최소 확인해야 하는 지표는 다음과 같다. - 홈 진입 대비 코스 시작률 - 코스 시작 대비 코스 완료율 - 위치 권한 허용률 - 자동 위치 감지 성공률 - 수동 체크 전환 비율 - 스팟 상세 진입률 - 외부 길찾기 클릭률 - 로컬 스팟 외부 링크 클릭률 - 찜 클릭 후 로그인 전환률 초기 목표값은 다음과 같이 둔다. - 코스 시작률 25% 이상 - 코스 완료율 40% 이상 - 위치 권한 허용률 50% 이상 - 자동 감지 성공률 65% 이상 - 로컬 링크 클릭률 15% 이상 ## 16. 출시 이후 우선순위 ### 16.1 출시 직후 개선 후보 - 혼잡도 기반 대체 스팟 제안 - 행사/계절성 배지 노출 - 코스 완료 공유 기능 ### 16.2 다음 단계 확장 - 반려동물 가능 여부 필터 공개 - 반려동물 전용 서브코스 출시 - 제휴 상권 리워드 또는 쿠폰 구조 검토 - 개인화 추천 고도화 ## 17. 결정 사항 요약 - 서비스 유형: 앱 퍼스트, 모바일 웹 연동 가능 구조 - 메인 타깃: 첫 방문 일반 관광객 + 커플 - 메인 경험: 수원화성 야경 데이트 코스 - 정보 구조: 코스 중심형 - 길안내: 외부 지도 앱 연결 - 로그인 정책: 비회원 우선, 필요 시 로그인 유도 - 미션 구조: 자동 위치 감지 + 수동 체크 하이브리드 - 로컬 연계: 정보 노출과 외부 링크까지만 제공 - 반려동물 전략: MVP 비노출, 내부 구조 선반영 이 문서는 달빛수원 MVP의 기준 기획 문서이며, 이후 구현 계획과 화면 설계, 데이터 모델링의 기준 입력값으로 사용한다.
