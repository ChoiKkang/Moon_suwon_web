# 승인 API 실데이터 검수 보고서

검수일: 2026-09-20 (Asia/Seoul)
대상: 승인·신청 완료 API 14건, 개발계정에서 운영계정 전환 신청 상태
원칙: 원천 성공과 공개 가능 여부를 분리하고, 검수되지 않은 원본·관계·이미지는 익명 앱 계약에 노출하지 않는다.

## 1. 결론

- 14개 API 관리대장과 운영 콘솔 표시를 구성했고, 원격 `ops.api_registry`에 14개 행이 존재한다.
- 운영 DB 마이그레이션 `20260919181438_scope_pet_enrichment_candidates`를 적용했다. `sync_list_pet_enrichment`는 `service_role`만 실행할 수 있고, 반려동물 공급자 발견 이력이 있는 ID만 상세 호출 대상으로 반환한다.
- 전체 실수집에서 인증·쿼터 오류는 없었다. 단, 경기도 버스 도착 API는 정류장 매핑 0건이므로 잘못된 정류장을 추측해 호출하지 않고 `hold`로 유지했다.
- 두루누비는 전국 140건을 정상 수집했지만 수원 교차 코스 0건이다. 이는 실패가 아니라 `healthy zero`이며, 수원 게시 데이터에는 영향을 주지 않는다.
- 사진·웰니스는 수원 범위/저작권 증거가 부족해 공개하지 않았고, 기초지자체·연관 관광지는 보수적인 장소 매칭과 게시 상태 검수 뒤 일부만 승인했다.
- 익명 앱 RPC는 신규 관계·날씨 데이터가 있는 장소와 없는 장소 모두 계약을 지키며 응답했고, `raw`/`core`/운영 스키마 직접 조회는 차단됐다.

검수 근거는 서비스 역할 RPC, `raw.sync_runs` 실행 메타데이터, 후보별 `review_status`/`review_note`, `public:verify`, `sync:rpc:verify` 결과다. 인증키·서비스 URL의 비밀값은 로그와 이 문서에 기록하지 않았다.

최종 재검증에서 `npm test` 163/163, lint, typecheck, production build, 원격 data health, 공개/관리자 경계 검증이 모두 통과했다. 버스는 매핑 0건의 명시적 `hold`로 분류하며, 로컬 smoke server에서 `/`, `/courses`, `/places/paldalmun`, `/robots.txt`, `/sitemap.xml`이 200, `/admin/operations`가 인증 리다이렉트(307)임을 확인했다.

## 4. 반려동물·혼잡도 커버리지 개선

### 반려동물

원인 분석 결과, 기존 보강 큐 147개 중 146개가 일반 `KorService2` 콘텐츠 ID였고, 전용 `KorPetTourService2/detailPetTour2`에서는 정상 빈 응답만 반복했다. 전용 발견 이력이 있는 ID는 1개였다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| 보강 큐 | 147 | 1 |
| 상세 API 시도 | 147 | 1 |
| 정상 빈 응답 | 147 수준 | 1 |
| 상세 호출 오류 | 0 | 0 |
| 공개 장소 fresh 정책 | 3/48 | 3/48 |

재수집 결과는 `discovered 8, enriching 1, detail success 1, source-empty 1, errors 0`이다. 현재 core 반려동물 정책 170건은 `fresh 21`, `unavailable 149`이고, 명시적 정책은 `allowed 17`, `partial 4`, `unknown 149`다. 빈 응답을 허용·불허로 추정하지 않고 `unavailable/unknown`으로 유지했다.

### 혼잡도

- 작업 기준 4개 구에서 2,250건을 조회해 core 미래 예측 1,680건을 정규화했다.
- 장소명은 정확한 KTO content ID 또는 유일한 공개 장소명만 매칭했다. 매칭되지 않은 관광지 56건은 공개하지 않았다.
- 미래 예측이 연결된 장소는 56곳, 그중 게시 장소는 19곳이다. 게시 장소 전체는 48곳이므로 공개 장소 29곳은 현재 연결 가능한 예측이 없다.
- 이전 기준 1,624행에서 1,680행으로 미래 core 범위가 늘었지만, 이를 실시간 현장 인원으로 표시하지 않는다. 앱 문구는 ‘방문 집중도 예측’으로 유지한다.

## 6. 두루누비와 버스 상태

### 두루누비

전국 응답 140건을 정상 수집했고, 수원 경계와 교차하는 검수 코스는 0건이었다. 따라서 `status=completed`, `zero_result=true`, `operational_status=completed`, `review_counts.excluded=140`으로 기록했다. 사용자가 지정한 대로 두루누비 수집 파이프라인은 유지하되, 수원 공개 장소·코스에는 아직 사용하지 않는다.

### 버스

경기도 버스도착정보 API는 정류소 ID가 필수인 실시간 서비스다. 현재 `core.place_bus_stops` 승인 매핑이 0건이므로 버스 도착을 호출하지 않았다. 임의 정류장 ID로 시험 호출하지 않고 `mapped_station_count=0`, `operational_status=hold`로 기록한 것이 검수 결과다. 정류소·노선 기준정보를 먼저 신청·검수한 뒤 화성행궁·수원화성 등 게시 장소 반경에 매핑하고, 그 이후에만 2분 캐시 도착 조회를 켠다.

## 7. 익명 앱 계약 실검증

공개 anon key로 다음 두 장소를 확인했다.

1. `장안공원-2741599` (`33ae1d9c-ba14-40e2-8bbb-a34675af86bd`): 검수된 연관 관광지 3건, 단기예보 150건, 중기예보 32건이 반환됐다.
2. `수원통닭거리-2613664` (`079b7372-e7a4-45ef-9f72-f07b3dc0afbd`): 연관 관광지 0건이어도 기존 장소·날씨 블록은 정상 반환됐다.

추가로 anon은 `raw.public_api_items`, `core.place_relations`, `core.place_photo_candidates`, `core.regional_visitor_stats`를 직접 조회할 수 없었다. 앱은 TourAPI를 직접 호출하지 않고 공개 RPC/serving contract만 사용한다. 계약 버전은 `docs/public-api-contract.md`의 additive block 계약이며, 중기예보는 기존 24시간 `weather_summary`와 섞지 않고 `mid_weather_summary`로 추가했다.

## 8. 지금 추가하기 좋은 API 후보

공식 포털의 현재 제공 설명·수정일과 달빛수원 앱의 이동·야간 산책 UX를 함께 평가했다.

### 최우선: 버스 정류소·노선 기준정보

현재 승인된 경기도 버스도착 API를 실제 앱 기능으로 만들기 위한 선행 데이터다.

- 후보: `경기도_정류소 조회`, `경기도_버스노선 조회`, `경기도_기반정보 관리`.
- 활용: 장소 반경 정류소 자동 후보화 → 운영자 위치·방향 검수 → `place_bus_stops` 승인 매핑 → 도착 API 2분 캐시.
- 판단: 기존 버스도착 승인 건을 살리는 가장 직접적인 후보. 정류장 ID·좌표·노선 방향이 확보되기 전에는 도착 API를 호출하지 않는다.
- 공식 확인: [경기도 버스정보 OpenAPI 목록·중단 공지](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000004150), [경기도 버스도착정보 조회](https://www.data.go.kr/data/15080346/openapi.do).

### 최우선: 기상청 초단기실황·초단기예보

새 승인 신청을 별도로 늘리기보다 현재 `기상청_단기예보 조회서비스`의 상세 기능을 확장하는 방식이 적절하다. 현재 서비스 설명상 초단기실황은 대표 AWS 관측값, 초단기예보는 발표시점부터 6시간을 제공한다.

- 활용: 야간 산책 시작 시각 기준 현재 기온·강수·풍속·6시간 강수 위험 표시.
- 검수: 관측값과 예보를 구분하고, 발표시각·격자·수집시각을 함께 저장한다.
- 공식 확인: [기상청 단기예보·초단기실황·초단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do).

### 상: 에어코리아 대기오염정보

한국환경공단 서비스는 측정소 실시간 PM10/PM2.5/오존, 통합대기환경지수와 예보 기능을 제공한다.

- 활용: 미세먼지·오존이 나쁜 날 야외 코스 경고, 어린이·반려동물 동반 코스 필터 보조.
- 검수: 수원 측정소 좌표와 측정시각을 기준으로 최근값만 표시하고, 결측 시 마지막 값에 `stale`을 부여한다.
- 주의: 대기질은 장소별 정밀 측정이 아니므로 ‘수원 측정소 기준’으로 표기한다.
- 공식 확인: [한국환경공단 에어코리아 대기오염정보](https://www.data.go.kr/data/15073861/openapi.do).

### 상: 수원 공영주차장 및 공중화장실 표준데이터

- [수원도시공사 공영주차장 현황](https://www.data.go.kr/data/15074539/fileData.do)은 주차장명·주소·구획수·요금·운영정보를 제공한다. 연간 파일이므로 실시간 잔여면이 아니라 ‘주차장 위치·요금 안내’로 사용한다.
- [전국공중화장실 표준데이터](https://www.data.go.kr/tcs/dss/selectDataSetList.do?dType=STD&keyword=%EC%A0%84%EA%B5%AD%EA%B3%B5%EC%A4%91%ED%99%94%EC%9E%A5%EC%8B%A4%ED%91%9C%EC%A4%80%EB%8D%B0%EC%9D%B4%ED%84%B0)는 야간 산책·무장애·반려동물 안내에 유용하다.
- 판단: 새 API 키보다 파일/표준데이터 수집 어댑터를 먼저 만들고, 주소·좌표·개방시간·장애인 편의시설을 검수한 뒤 장소 상세의 주변 편의시설 블록으로 공개한다.

### 중: 다국어 KTO 관광정보

현재 국문만 active다. 영문을 1순위, 일문·중문 간체를 2순위로 추가하면 외국인 방문자용 장소명·소개·운영시간을 제공할 수 있다. KTO 영문 서비스는 VisitKorea 영문 데이터 약 8만 건을 제공하고 운영계정 심사가 별도이므로, 수원 장소 ID를 국문 원장과 정확히 매칭하고 번역 원문을 덮어쓰지 않는 additive locale 테이블로 저장한다.

- 공식 확인: [한국관광공사 영문 관광정보서비스](https://www.data.go.kr/data/15101753/openapi.do), [KTO 제공 API 목록 공지](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000004371).

### 중: 관광공모전 수상작·고캠핑

- 관광사진 API의 저작권 증거 부족을 보완할 수 있는 `관광공모전(사진) 수상작 정보`는 수상작별 이용조건·원본 출처를 확인할 수 있을 때만 별도 후보로 검토한다. 승인 전에는 이미지 URL을 공개하지 않는다.
- `한국관광공사_고캠핑 정보 조회서비스_GW`는 야영장·편의/안전시설 정보를 제공한다. 수원 시내 야간 산책 핵심과 거리가 있어 수원 결과가 충분할 때만 도입한다.
- 공식 확인: [한국관광공사 고캠핑 정보 조회서비스](https://www.data.go.kr/data/15101933/openapi.do), [KTO 수상작 포함 API 목록](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000004371).

### 낮음: 의료관광·관광인 채용·관광 수요 지표

의료관광·채용은 현재 앱의 야간 산책 핵심과 직접 연결되지 않는다. 관광 수요 강도·관광자원 수요·지역 관광 다양성은 운영자 코스 우선순위와 공모전 분석에는 유용하지만 방문자 수·혼잡도와 섞어 공개하면 의미가 달라지므로 `internal_analysis`로 별도 적재한다.

## 9. 개발계정 → 운영계정 전환 체크리스트

- [ ] 공공데이터포털에서 14개 서비스 각각의 운영계정 승인·만료일·일일/초당 트래픽을 확인한다.
- [ ] 운영계정 신청 시 공모전 접수처와 실제 사용 URL/앱 기능을 등록하고, 승인 전에는 개발계정 결과를 운영 데이터로 간주하지 않는다.
- [ ] `KTO_SERVICE_KEY`, `KMA_SERVICE_KEY`, `GG_BUS_SERVICE_KEY`를 제공처별 서버 전용 secret으로 분리한다. 호환 fallback은 `KTO_SERVICE_KEY`이며 브라우저 환경변수로 만들지 않는다.
- [ ] GitHub Actions와 Vercel Production에 secret을 각각 등록하고, 값 자체는 로그·문서·커밋에 남기지 않는다.
- [ ] `--dry-run --limit 2`로 모든 작업을 먼저 확인하고, `bus_arrival`은 승인 정류장 매핑이 1건 이상일 때만 호출한다.
- [ ] 운영계정 전환 직후 날씨 → KTO 후보 → 방문자 분석 → 버스 순서로 작은 실행을 하고, 인증/쿼터 오류가 나면 반복 호출하지 않고 포털 승인·키·트래픽을 먼저 점검한다.
- [ ] 실행 뒤 `npm run data:verify -- --job all`, `npm run public:verify`, `npm run admin:verify`, `npm run deployment:verify`를 실행한다.
- [ ] 운영 계정 승인 전후의 `raw.sync_runs` 상태, 4개 구 완전성, `healthy zero`/`hold` 사유를 운영 콘솔에 남긴다.
- [ ] 모바일 앱은 `docs/public-api-contract.md`의 additive 계약을 기준으로 배포하고, 모르는 신규 키는 무시하며 `items=[]`를 정상 빈 블록으로 처리한다.

## 10. 재현 명령

비밀값은 출력하지 않고 저장소의 `.env.local`을 Node의 환경 파일 옵션으로만 주입한다.

```bash
node --env-file=../../.env.local node_modules/tsx/dist/cli.mjs scripts/sync-kto-data.ts --job pet
node --env-file=../../.env.local node_modules/tsx/dist/cli.mjs scripts/verify-sync-rpc.ts
node --env-file=../../.env.local node_modules/tsx/dist/cli.mjs scripts/verify-public-boundary.ts
npm run data:verify -- --job all
```

마지막 반려동물 실행은 `discovered 8 / enriching 1 / detail success 1 / source-empty 1 / errors 0`이었다. 큐가 다시 일반 콘텐츠로 넓어지면 `raw.kto_pet_candidates`와 `public.sync_list_pet_enrichment`의 공급자 발견 조건을 먼저 확인한다.
