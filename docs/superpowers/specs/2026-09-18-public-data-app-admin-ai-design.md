# 달빛수원 공공데이터·앱 계약·관리자 자동화·AI 코스 설계

- 작성일: 2026-09-18
- 상태: 설계 승인 완료, 구현 전
- 대상 저장소: `moon_suwon` 웹 저장소
- 관련 저장소: [ChoiKkang/MoonSuwonApp](https://github.com/ChoiKkang/MoonSuwonApp) (`develop` 기준, 이 설계 단계에서는 수정하지 않음)

## 1. 목적과 범위

달빛수원 웹의 주 역할은 모바일 앱을 홍보하는 공개 웹사이트와 운영자가 콘텐츠·데이터를 관리하는 관리자 콘솔이다. 모바일 앱이 주 서비스이므로 웹 DB, API, 인증, 동기화 계약은 친구 앱이 안정적으로 소비할 수 있는 공개 계약을 우선한다.

이번 작업의 목표는 다음과 같다.

1. 한국관광공사 공공데이터를 발견·보강·검수·공개하는 파이프라인을 만든다.
2. 친구 앱이 `raw`/`core` 내부 구조를 몰라도 공개 RPC만으로 장소·코스·행사·반려동물·혼잡도 정보를 사용할 수 있게 한다.
3. 관리자에게 수집 신선도, 실패 원인, 신규 후보, 승인 상태를 한 화면에서 제공한다.
4. 코스 품질을 결정론적 제약조건으로 보장하고 AI는 근거가 있는 초안 생성과 후보 정렬만 보조하게 한다.
5. 공개 웹과 관리자 콘솔의 상태 표현, 반응형, 접근성, 오류 복구 경험을 통일한다.

### 범위 밖

- 모바일 앱 저장소 직접 수정
- 새 장소·코스의 자동 공개
- 실시간 인원 수를 제공하는 혼잡도 시스템 구축
- 앱에 `service_role` 또는 원천 API 키 배포
- 웹훅/Discord 알림 체계 변경
- 승인되지 않은 유료 경로 API나 AI 공급자 도입

## 2. 현재 조사 결과

2026-09-18 기준 웹 저장소, 원격 Supabase, 친구 앱 `develop` 브랜치를 읽기 전용으로 대조했다.

- 현재 웹 DB에는 활성 장소 44곳, `place_sources` 동기화 대상 44곳, 원시 반려동물 데이터 3건, 정책 행 14건이 있다.
- 기존 반려동물 작업은 등록된 44곳에 대한 `detailPetTour2` 상세조회에 한정되어 신규 장소를 발견하지 못한다.
- 공식 반려동물 목록 API로 수원 지역을 조회하면 후보 약 267건이 확인된다. 후보 발견과 기존 상세 보강을 분리해야 한다.
- 최신 실행 기록에는 timeout/abort를 포함한 반려동물 상세 오류가 누적되어 있다. 성공한 빈 결과와 네트워크/API 오류를 같은 실패로 처리하면 안 된다.
- 친구 앱의 장소 DTO에는 반려동물 필드가 있으나 Supabase 응답 매핑이 빠져 기본값 `partial`이 표시될 수 있다.
- 현재 공개 RPC와 뷰는 공개·활성 게이트를 갖지만 장소 상세·주변 장소·코스 상세의 반려동물 필드가 완전하지 않다.
- 현재 코스 초안 생성기는 `heuristic-v1` 기반의 결정론적 초안이며, 가까운 장소 연결과 직선거리 계산을 사용한다. AI를 먼저 넣기보다 후보·경로 검증을 강화해야 한다.

## 3. 승인된 접근 방식

선택한 방식은 **공개 계약을 먼저 안정화하는 점진 확장안**이다.

```text
한국관광공사 API
  → raw 원문·수집 로그
  → core 정규화·소스 매핑
  → editorial 검수·공개 상태
  → serving/public 뷰·RPC
  → 친구 앱·공개 웹
```

자동 수집 또는 AI가 만든 데이터는 검수 대기 상태로 저장한다. `is_published=true`이면서 `is_active=true`인 데이터만 공개 RPC가 반환한다.

## 4. 데이터 경계와 계약

### 4.1 계층별 책임

| 계층 | 책임 | 공개 여부 |
| --- | --- | --- |
| `raw` | KTO 원문, 페이지 스냅샷, 실행/오류 로그 | 공개하지 않음 |
| `core` | 장소·소스·정규화 정책·관계 | 공개하지 않음 |
| `editorial` | 제목, 설명, 이미지 선택, 검수·공개 상태 | 공개 RPC를 통해서만 |
| `serving` | 앱/웹에 필요한 조합과 파생 값 | 직접 접근 대신 RPC 권장 |
| `public` | 공개·활성 데이터에 대한 안정적인 RPC/뷰 | 익명 읽기 허용 범위를 명시 |

친구 앱은 publishable key로 `public` RPC만 호출한다. 서비스 역할 키, `raw`, `core`, 내부 관리자 함수는 앱에 배포하지 않는다.

### 4.2 장소 공개 계약

기존 함수 이름과 필드는 유지하고, 필요한 값만 추가한다. 기존 앱이 모르는 JSON 키나 테이블 열은 무시할 수 있도록 additive 변경을 우선한다. 기존 의미를 바꾸는 breaking 변경이 필요할 때만 명시적 `v2` 함수를 만든다.

`get_place_by_slug`, 주변 장소 RPC, 코스 상세의 장소 항목에 다음 필드를 추가한다.

| 필드 | 값 | 의미 |
| --- | --- | --- |
| `pet_policy` | `allowed \| partial \| not_allowed \| unknown` | 앱 표시용 정규화 정책 |
| `pet_note` | 짧은 문자열 | 사용자에게 보여줄 주의/조건 안내 |
| `pet_data_status` | `fresh \| stale \| unavailable \| unknown` | 원천 신선도·가용성 |
| `pet_source_updated_at` | timestamp/null | KTO 원천 수정 시각 |
| `crowd_forecast` | 날짜별 구조화 값/null | 상대 집중률 예측, 실시간 인원 아님 |
| `crowd_data_status` | `fresh \| stale \| unavailable` | 혼잡도 데이터 상태 |

응답에는 가능하면 `contract_version`과 `generated_at`을 추가해 앱이 계약 버전을 확인할 수 있게 한다. 공개 함수는 내부적으로 항상 공개·활성 조건을 검사한다.

친구 앱에서는 `pet_policy`와 `pet_note`를 DTO에 매핑하고, `unknown`은 `partial`로 변환하지 않는다. 이 앱 변경은 별도 저장소의 친구 작업으로 전달하며 웹 저장소에서 앱 코드를 수정하지 않는다.

### 4.3 코스 공개 계약

코스 수준의 `pet_ready_flag`와 각 정류장의 `pet_policy`, `pet_note`를 함께 반환한다. 코스 플래그는 모든 정류장의 정책과 코스 생성 시점의 검증 결과를 바탕으로 계산하며, 개별 장소 제한이 숨겨지지 않게 한다.

## 5. 공공데이터 수집 설계

공식 서비스와 적용 목적은 다음과 같다.

- 일반 관광지: `KorService2` 지역 목록·상세·이미지
- 반려동물: `KorPetTourService2/petTourSyncList2`, `detailPetTour2`
- 행사: `KorService2/searchFestival2`
- 혼잡도: `TatsCnctrRateService/tatsCnctrRatedList`

참고 명세: [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do?recommendDataYn=Y), [관광지 집중률 방문자 추이 예측 정보](https://www.data.go.kr/data/15128555/openapi.do), [TourAPI 운영 포털](https://api.visitkorea.or.kr/).

혼잡도 API는 향후 30일의 상대 집중률 예측을 제공하는 서비스이지 실시간 방문자 수가 아니다. UI와 앱 문구 모두 이 의미를 명확히 표시한다. 개발 트래픽·초당 제한·점검이 존재하므로 모든 작업은 제한된 동시성, 재시도, 쿼터 중단을 지원한다.

### 5.1 발견 → 보강 → 검수 → 공개

1. **발견**: 수원 지역 코드 41, 시군구 111/113/115/117, 반려동물 콘텐츠 타입 12/14/15/28/32/38/39를 페이지 단위로 조회한다. `contentid`를 기준으로 중복 제거하고 원문·조회 시각을 저장한다.
2. **보강**: 신규·변경 후보만 상세·이미지를 조회한다. 반려동물 동반 가능 여부, 주의사항, 사고 위험, 관련 시설, 구매·대여 정보를 raw에 보존하고 앱용 정책/짧은 안내를 core에 정규화한다.
3. **검수**: 신규·변경·unknown·오래된·실패·좌표/이미지 누락 후보를 관리자 검수함에 넣는다.
4. **공개**: 관리자가 승인한 장소만 editorial 공개 상태로 전환한다. 수집 성공은 공개 승인으로 간주하지 않는다.

### 5.2 실행 주기와 복구

- 혼잡도: 매일
- 행사: 매일
- 반려동물 목록 발견: 매일
- 반려동물 상세 보강: 변경분 매일, 전체 재검증 주간
- 일반 관광지/이미지: 변경분 주간, 전체 재검증 월간
- 모든 작업: GitHub Actions 수동 실행과 `dry-run` 지원

각 실행은 `running`, `succeeded`, `partial`, `failed`, `quota_stopped` 중 하나로 기록한다. `raw.sync_runs.metadata`에는 후보 수, 상세 성공 수, 정책 매칭 수, 빈 결과 수, stale 수, 결과 코드별 오류 수를 저장한다. 빈 성공 응답은 오류로 기록하지 않는다.

네트워크 timeout/abort는 지수 백오프로 제한 재시도한다. 반복 실패는 다음 실행으로 넘기고 마지막 정상 데이터를 유지한다. API 키나 전체 요청 URL은 로그에 남기지 않는다. 동시 실행 잠금과 idempotency key로 중복 upsert를 방지한다.

### 5.3 신선도 정책

데이터 종류별 SLA를 UI에 표시한다.

- 혼잡도: 마지막 성공으로부터 26시간 이내면 `fresh`
- 행사: 48시간 이내면 `fresh`
- 반려동물 정책: 8일 이내면 `fresh`
- 일반 장소/이미지: 8일 이내면 `fresh`

SLA를 넘으면 기존 값은 삭제하지 않고 `stale`로 표시한다. 수동 정책은 원천 실패나 stale에도 유지한다.

## 6. 관리자 운영 설계

### 6.1 화면 구조

- 운영 현황
- 장소 검수
- 코스 초안
- 행사
- 동기화 이력

운영 현황에는 데이터별 마지막 성공 시각, 공개 수, 검수 대기 수, 오래된 데이터 수, 최근 오류, 반려동물 정책 커버리지, 혼잡도 최신 예측 날짜를 표시한다.

### 6.2 검수함

검수자는 KTO 원문, 정규화값, 현재 공개값, 지도 위치, 이미지, 변경 이력을 한 화면에서 비교한다. 승인, 반려, 보류, 개별 재수집, 일괄 승인/반려를 제공한다. 수동 수정에는 `is_manual_override=true`와 관리자·시각을 기록한다.

### 6.3 작업 제어

관리자 인증 후 서버 측에서만 GitHub Actions 또는 안전한 작업 큐를 호출한다. 브라우저에는 GitHub 토큰, Supabase service role, KTO 키를 전달하지 않는다. 작업 종류, 지역, 최대 처리 건수, `dry-run`, 실패 항목만 재시도 옵션을 지원하고 실행 결과는 `raw.sync_runs`로 통합한다.

## 7. 코스 생성과 AI 보조

### 7.1 결정론적 후보 생성

공개·활성이고 좌표가 있는 장소만 대상으로 여러 후보를 생성한다. 다음은 하드 제약이다.

- 비공개/비활성/좌표 누락/중복 장소 제외
- 운영시간·휴무일 충돌 제외
- 총 거리와 예상 시간 상한 준수
- 반려동물 코스는 모든 정류장의 정책 조건 준수
- 오래된 데이터, 혼잡도 충돌, 이미지·설명 누락은 감점 또는 제외

점수는 테마 적합도, 이동 효율, 야간 볼거리, 장소 다양성, 반려동물 편의, 혼잡도, 콘텐츠 완성도, 데이터 신선도를 조합한다. 실제 경로 API가 없으면 직선거리로 계산하고 사용자에게 도보 시간이라고 표시하지 않는다.

### 7.2 AI 제한

AI에는 후보 장소 ID와 검증된 구조화 정보만 전달한다. AI는 장소 ID, 좌표, 운영시간, 가격을 새로 만들 수 없다. 허용 출력은 제목, 소개, 장소별 포함 이유, 주의사항, 후보 우선순위이며 JSON 스키마로 검증한다.

검증 실패, 근거 불일치, 존재하지 않는 ID, 숫자 변조, 과장 문구가 있으면 AI 결과를 폐기하고 결정론적 템플릿을 사용한다. AI가 비활성화되거나 API가 실패해도 코스 초안 생성은 계속되어야 한다.

각 초안에는 `automation_source`, 모델, 프롬프트 버전, 후보 입력 checksum, 사용 근거, 생성 시각, 승인/반려 이력을 저장한다. 모든 AI 코스는 관리자 승인 전까지 비공개다.

도입 순서는 결정론적 후보/경로 검증 → AI 제목·설명 → 검증 데이터가 축적된 뒤 AI 후보 재정렬이다.

## 8. 디자인·접근성

현재 달빛수원의 어두운 네이비·달빛 골드·유리 질감과 Manrope 중심의 시각 언어를 유지한다. 임의의 전면 재설계 대신 운영에 필요한 구성요소를 토큰화한다.

- 상태 배지: 텍스트·아이콘·색상을 함께 사용
- 공통 카드, 테이블, 상세 패널, 확인 모달
- 로딩 skeleton, 빈 결과, 부분 성공, 오래됨, 권한 없음, 재시도 상태
- 작은 화면에서 표를 카드 또는 가로 스크롤로 변환
- 키보드 포커스와 충분한 명도 대비
- `prefers-reduced-motion` 존중
- 오류 메시지에 원인과 다음 행동 표시

공개 웹은 앱 홍보와 승인된 대표 콘텐츠를 우선하고, 관리자 콘솔은 데이터 신선도와 검수 흐름을 우선한다. 두 영역의 상태·버튼·경고 문구는 같은 디자인 토큰을 사용한다.

## 9. 보안과 권한

- 앱은 Supabase publishable key와 공개 RPC만 사용한다.
- `raw`, `core`, 내부 editorial 테이블의 익명 직접 읽기 권한을 부여하지 않는다.
- 공개 RPC는 내부에서 `is_published=true AND is_active=true`를 강제한다.
- 인증이 필요한 체크인 함수는 `anon` 실행 권한을 제거하고 `authenticated`만 허용한다.
- service role은 GitHub Actions/서버 실행 환경에서만 사용한다.
- 외부 원문은 데이터로 취급하고 AI 프롬프트 지시로 실행하지 않는다.
- 로그에는 키, 쿠키, 전체 민감 요청값을 기록하지 않는다.

## 10. 검증과 완료 기준

### 자동 검증

- 공개 RPC 응답 계약 snapshot/fixture 테스트
- raw/core 직접 공개 권한과 RLS 검사
- timeout, 쿼터, 빈 결과, 점검 응답 테스트
- 재실행 idempotency와 중복 방지 테스트
- 수동 override 보존 테스트
- 후보 경로 거리·시간·반려동물 하드 제약 테스트
- AI JSON 스키마·근거·장소 ID 검증 테스트
- 주요 공개 웹/관리자 브라우저 흐름 테스트

### 완료 조건

1. 친구 앱이 공개 RPC로 장소·코스·반려동물·혼잡도 데이터를 읽을 수 있다.
2. `unknown` 정책이 `partial`로 오표시되지 않는다.
3. 신규 KTO 후보가 자동 공개되지 않고 검수함에 도착한다.
4. API 장애 시 마지막 정상 데이터와 stale 상태가 유지된다.
5. 관리자가 실패 원인과 재시도 방법을 한 화면에서 확인할 수 있다.
6. AI 결과에서 존재하지 않는 장소, 하드 제약 위반, 근거 없는 사실이 공개되지 않는다.
7. raw/core/service role이 앱에 노출되지 않는다.
8. 모바일·데스크톱에서 공개 웹과 관리자 핵심 흐름을 사용할 수 있다.

## 11. 구현 순서

1. Supabase additive 스키마와 공개 RPC 계약, 권한 수정
2. 기존 반려동물 데이터 backfill 및 공개 계약 fixture 작성
3. 반려동물 목록 발견·상세 보강·오류복구 파이프라인
4. 관리자 운영 대시보드와 검수함
5. 친구 앱 담당자에게 RPC 계약/fixture 전달
6. 결정론적 코스 후보·경로 품질 개선
7. 관리자 검수형 AI 초안 생성
8. 전체 브라우저·장애·보안 검증

모든 단계는 기존 공개 RPC의 하위 호환을 유지하며, 각 단계가 검증된 뒤 다음 단계로 이동한다.
