# 달빛수원 KTO 콘텐츠 적용 방향

## 결론

달빛수원은 공공데이터 기반 관광 DB가 아니라, 공공데이터로 신뢰도를 확보한 야간 큐레이션 서비스로 간다.

## 데이터 역할

- TourAPI: 관광지명, 주소, 좌표, 원문 개요, 이미지, contentid 기준 동기화
- core: 정규화된 기준 데이터
- editorial: 야간 포인트, 포토팁, 미션, SEO 문구
- serving: 앱/웹이 읽는 완성 데이터

## 추천 코스

1. 성곽 야경 입문 코스: 연무대, 동북공심돈, 봉돈, 지동벽화마을, 수원통닭거리
   - KTO 적재 후보: 연무대, 동북공심돈, 봉돈, 수원통닭거리, 수원 지동벽화마을
   - 앱 방향: 첫 방문자에게 “검증된 공식 스팟 + 야간 동선”을 제공한다.
2. 사진 중심 코스: 방화수류정, 화홍문, 용연, 성곽 조망 지점
   - KTO 미포함 또는 검색 불안정 후보는 자체 스팟으로 관리한다.
   - 앱 방향: 시간대, 삼각대 필요 여부, 반사 사진 포인트를 editorial에 축적한다.
3. 로컬 상권 연결 코스: 수원통닭거리, 행궁동 카페, 소품샵, 전통시장 후보
   - KTO는 기준 위치와 공신력 보강에 쓰고, 실제 매장 큐레이션은 운영 데이터로 분리한다.
   - 앱 방향: 관광 이후 소비 전환을 유도하는 “마무리 스팟”으로 설계한다.

## 다음 확장 아이디어

- 위치 기반 추천: 현재 위치에서 15분 안에 갈 수 있는 야간 스팟을 우선 노출한다.
- 날씨/시간대 큐레이션: 비 오는 날, 노을 직후, 늦은 밤처럼 방문 조건별 추천 문구를 editorial에 추가한다.
- 미션형 방문: 각 장소별 `mission_title`, `mission_body`, `mission_radius_m`를 활용해 체크인과 사진 미션을 붙인다.
- KTO 동기화 정책: 공공데이터는 월 1회 또는 배포 전 수동 동기화하고, 노출 문구는 운영자가 승인한 뒤 공개한다.

## 운영 원칙

- 앱과 웹은 TourAPI를 직접 호출하지 않는다.
- TourAPI 키는 서버/Edge Function Secret에만 둔다.
- KTO에 없는 핵심 스팟은 자체 스팟으로 관리한다.
- 공공데이터 개요는 참고 원문으로 보존하고, 노출 문구는 editorial에서 작성한다.
- Supabase 앱 조회는 `serving` 계층만 사용하고, 원천 데이터 편집은 서버 전용 키로만 수행한다.
